# Agent instructions

## Project state
This repository is at the pre-product bootstrap stage. Its purpose, users, requirements, implementation, and technology choices are **TBD**; do not infer or invent them. The `docs/` wiki is the authoritative place for verified project context. Start with [docs/INDEX.md](docs/INDEX.md), then read only the documents relevant to the task.

## Working rules
- Inspect the current files and available Git status before editing. Preserve existing work and keep changes scoped to the request.
- Follow established conventions once they exist. Until then, avoid choosing a language, framework, architecture, or dependency without a documented need and approval where required.
- Verify changes with relevant checks. The project has no known build or test commands yet; do not claim checks that were not run. See [docs/TESTING.md](docs/TESTING.md).
- Do not expose, commit, or copy secrets or personal data. Minimize dependencies; do not install packages, add paid services, or make external changes without explicit approval.
- Keep changes reviewable. Do not rewrite history, discard user changes, or commit unless asked. Report the actual Git state; Git metadata may not be initialized.
- Record stable, verified facts in the relevant wiki page. Keep temporary task notes in the task or handover, not permanent docs. Update docs when implementation, setup, tests, or decisions change.
- Ask before proceeding when a choice materially affects product scope, security/privacy, cost, external services, or irreversible changes and cannot be resolved from authoritative project information.
- For handoff, use [docs/HANDOVER.md](docs/HANDOVER.md), inspect the recipient's work before integrating, and include the current state and next action.
