# Known issues and limitations

- This is an unsigned Windows beta. Enterprise execution policies and clean installations on other machines are unverified. No paid signing service was purchased.
- Compatibility depends on the installed desktop app honoring separate data roots and activation links. Diagnostics distinguish locally observed builds from unverified future builds; version recognition is not a comprehensive certification.
- Connector authorization return routing remains unresolved. Installed app 26.1013.4894.0 uses `codex://connector/oauth_callback`; the owner reported that browser authorization opens the default ChatGPT window. On 2026-10-21 the owner rejected manual work, including Windows default-handler selection. The callback account-picker prototype is therefore inactive at startup, and its callback/watchdog entry points are excluded from release packaging. A unique disposable protocol successfully dispatched to a synthetic handler, whereas the existing `codex` scheme did not. This narrows the Windows failure but does not establish a safe automatic solution. All probes cleaned up and retained the original empty `codex` stub. No protected default preference, credentials, or installed app code was changed. See [routing limits](../launcher/README.md#plugin-authorization-returns). Installing in the default app does not verify availability in an isolated profile.
- Candidate alternative added on 2026-10-21: **Plugins...** opens the directory inside the selected profile's built-in browser, whose installed code handles connector callbacks internally. Live probes confirmed direct browser delivery and preserved the original profile process, and a synthetic return was intercepted without navigation out of the probe tab. GitHub subsequently became installed/enabled in this profile's active chat, and an authenticated read-only login request succeeded. The completed authorization path was not observed, so the candidate's causal role and repeatability remain unverified. No user Windows setup is required by this candidate, but ordinary authentication/consent remains necessary. An embedded browser may be restricted by a provider; do not infer universal plugin support.
- Profile labels are supplied by the user, not verified account identities. Separate folders do not enforce filesystem or employer-policy isolation.
- Full close forcefully interrupts the selected profile's tasks. It preserves disk data, warns in the UI, and rechecks process identity; it does not inspect whether agent work is complete.
- Local tests cover dispatch of the documented workspace link. Signed-in navigation across every supported desktop version and independent beta installations remain unverified.
- The Windows Forms process/window queries are synchronous. Cold launches may keep the launcher busy for up to the 30-second wait; this does not stop running Codex tasks.
- Global hotkeys can conflict with other apps; unavailable bindings are reported and tray actions remain available. Native registration tests do not run successfully inside the restricted agent sandbox.
- Closing/minimizing the new launcher hides it to the tray; use **Exit launcher** to quit. Old monolithic launcher processes from before this upgrade do not participate in the new singleton protocol.
- Removal preserves account data, unknown files and edited application files. A retained data folder is intentional, not a complete wipe.
